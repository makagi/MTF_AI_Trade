# トレード分析AIエージェント用 プロンプト集 (Agent Prompts)

AIエージェント（Antigravity, Cursor, Cline, Claude Code, ChatGPT等）にシステムトレードの分析を依頼する際、またはエージェントのシステム指示（Custom Instructions / `AGENTS.md`）として利用するためのプロンプト集です。

---

## 1. システムプロンプト（エージェント常駐用）

エージェントの振る舞いやナレッジベース運用規約を固定するためのベース指示です。
プロジェクトの `AGENTS.md` や、各種エージェントの設定（System Prompt）にコピペして使用します。

```markdown
あなたは「MTF_AI_Trade」専属のクオンツ・リサーチエージェントです。
市場データから統計的エッジを探求・検証し、得られた知見を自己完結した「Analysis Record」および「Knowledge Lineage（知識系譜）」としてナレッジベースに蓄積することがあなたの任務です。

【運用原則と規約】
1. スクリプトや生成画像をプロジェクトルートに直接作成・散乱させてはならない。
2. すべての分析は必ず `python tools/kb.py new` を使用して `knowledge/records/YYYY-MM/ANL-...` 配下に作成すること。
3. 1つの分析ディレクトリ内に以下の5要素を必ず自己完結させること：
   - `record.md`: 目的・数式・結果の考察・客観的事実(FIND)・仮説(HYP)
   - `config.yaml`: 対象期間・閾値パラメータ
   - `run.py`: 単独で再実行可能なPythonコード（外部からインポートされる前提にしない）
   - `metrics.json`: サンプル数、勝率、期待値、および実行環境メタデータ
   - `artifacts/`: 生成されたグラフ画像
4. 過去の分析から派生・発展させる場合は、必ず `--derived-from ANL-xxxx` を指定し、系譜を繋ぐこと。
5. 分析・実行が完了したら、必ず以下のコマンドを実行してインデックスを更新・検証すること：
   - `python tools/kb.py index`
   - `python tools/kb.py validate`
6. 定性的な希望的観測を排除し、摩擦コスト（取引手数料＋スリッページ）控除後の期待値と統計的有意性に基づき冷徹に評価すること。
```

## 2. タスクプロンプト（ユーザー指示テンプレート）

日々の分析作業で、エージェントへチャット欄から指示を出す際のコピペ用テンプレートです。

### テンプレート A: 過去の知見を調査・回答させる

過去にどのような分析が行われ、何が分かっていて何が未解決かをAIに調べさせるプロンプトです。

```markdown
ナレッジベース（knowledge/index.json および LINEAGE.md）を参照し、以下のテーマについて過去に分かっていることを整理してください。

【調査対象】
- 銘柄: BTCUSD
- 時間足: 1h
- テーマ/キーワード: [例: Mean Reversion / スクイーズ / 曜日効果 / セッションブレイク]

【回答に含めるべき内容】
1. 該当する Analysis Record (ANL-xxx) の一覧と要約
2. 既に実証された客観的事実（FIND）
3. 未検証または検証途中の仮説（HYP）
4. これまでの検証で判明した課題・コスト負け要因
5. 次に検証すべき優先度の高い分析テーマの提案
```

---

### テンプレート B: 新規仮説の分析とレコード作成

新しいアイデアや市場の歪みを検証し、分析レコードとして保存させるプロンプトです。

```markdown
以下の仮説について、ナレッジベースの規約に沿って新規分析を実行し、Analysis Record を作成してください。

【分析テーマ】: [例: 24時間安値更新後の押し目買いの優位性検証]
【対象銘柄】: BTCUSD
【時間足】: 1h
【データセット】: BTCUSD_1H_DISCOVERY (2020-2023)
【仮説】: [例: 前日安値を下回った後、オシレーターが売られすぎ圏にある場合、24時間のフォワードリターンがプラスに偏るのではないか？]

【実行要件】
1. `python tools/kb.py new --title "..." --symbol BTCUSD --timeframe 1h --slug ...` で新規レコードを作成。
2. `config.yaml` にパラメータを定義。
3. `run.py` を実装し、無条件ベースライン（全サンプル）とシグナル抽出時の勝率・平均リターン・Sharpeを比較。
4. フォワードリターン分布を `artifacts/distribution.png` に保存。
5. `metrics.json` に実行メタデータと結果を出力。
6. `record.md` に背景、数式（LaTeX）、考察、客観的事実（FIND）、および次の仮説（HYP）を記述。
7. 完了後に `python tools/kb.py index` と `python tools/kb.py validate` を実行すること。
```

---

### テンプレート C: 過去分析の継承と派生検証（Lineageの発展）

既存の分析レコード（ANL-xxx）で得られた知見を元に、条件追加やパラメータ変更、別期間での検証を行わせるプロンプトです。

```markdown
先行分析 `[例: ANL-20260922-001]` から派生した以下の仮説を検証してください。

【派生元分析】: [例: ANL-20260922-001 (SMA -2 ATR Mean Reversion)]
【検証する仮説】: [例: 先行分析で見られた下落トレンド中のテールリスクを排除するため、長期SMAの傾き（Slope > 0）を条件に追加すると期待値が向上するか？]
【対象期間】: [例: BTCUSD_1H_DISCOVERY または BTCUSD_1H_VALIDATION]

【実行要件】
1. `python tools/kb.py new --title "..." --derived-from [先行分析ID] --slug ...` で派生レコードを作成。
2. 先行分析のロジックを継承し、今回の追加フィルター/変更点を反映した `run.py` を作成・実行。
3. 先行分析の結果と直接比較し、仮説が「支持（Confirmed）」されたか「棄却（Rejected）」されたかを定量的に評価。
4. `record.md` に先行分析からの改善点・残存課題、新しい FIND と HYP を明記。
5. `python tools/kb.py index` を実行して系譜グラフを更新し、結果を報告してください。
```

### テンプレート D: 2024年（Validation期間）での一発勝負テスト

Discovery期間（2020-2023）で見つかった有望なエッジが、過学習（カーブフィッティング）でないかを検証期間でテストさせるプロンプトです。

```markdown
Discovery期間で有望だった分析 `[例: ANL-20260922-002]` について、未見のValidation期間（2024年）を用いて一発勝負の頑健性検証を行ってください。

【対象分析】: [例: ANL-20260922-002]
【データセット】: BTCUSD_1H_VALIDATION (2024-01-01〜2024-12-31)

【実行要件】
1. `python tools/kb.py new --title "[元タイトル] - 2024 Out-of-Sample Validation" --derived-from [元分析ID] --dataset BTCUSD_1H_VALIDATION --start-date 2024-01-01 --end-date 2024-12-31 --slug oos_validation` でレコード作成。
2. パラメータの最適化・再探索は一切行わず、元分析と同一パラメータで `run.py` を実行。
3. Discovery期間（2020-2023）とValidation期間（2024）のパフォーマンス乖離（Performance Degradation）を比較。
4. エッジが本物（生き残った）か、過学習による幻想（劣化・消滅）だったかを `record.md` に結論付け、インデックスを更新してください。
```
